相机以倾斜角度拍摄屏幕、表格或面板时，目标会呈现梯形，远端缩短、近端放大。若后续算法直接在原图上做 OCR、测距或区域比较，相同物理长度会对应不同像素尺度。

这个项目把问题拆成两步：先用 YOLO 实例分割找到目标 mask，再从 mask 估计四边形，通过单应变换生成正视图。它同时提供图像/文件夹推理、视频逐帧推理、轻量与完整两种几何后端，以及从标注转换、数据增强到 YOLO 训练的工具链。

## 1. 为什么检测框不够

目标检测框始终是水平矩形。对旋转或强透视目标，它会包含大量背景，也无法提供目标的四个真实角点。透视矫正需要的是源平面上的四个对应点，而不是一个轴对齐框。

实例分割 mask 具有三项优势：

1. 描述目标实际轮廓，而不仅是外接矩形；
2. 可以通过轮廓、凸包和支撑线估计四条边；
3. 能识别目标是否贴边、缺角或被遮挡，并选择不同回退策略。

代价是 mask 边界也会受模型误差影响。边缘外扩几个像素、缺少一个角或把背景并入目标，都会改变估计四边形并传导到正视图。

## 2. YOLO mask 如何恢复到原图尺寸

Ultralytics 结果可能提供两种 mask 表示：

- `masks.xy`：已经映射到原图坐标的多边形点；
- `masks.data`：模型推理分辨率上的 mask tensor。

代码优先使用多边形，在原图大小的空白 mask 上调用 `fillPoly`；若不可用，再尝试用 Ultralytics 的 `scale_masks` 恢复尺寸，最后还有 OpenCV resize 回退。

```text
if result has polygon:
    fill polygon on H x W mask
else if scale_masks available:
    resize tensor with library geometry
else:
    interpolate tensor to H x W and threshold at 0.5
```

这个顺序避免把低分辨率 mask 直接当原图坐标。不同回退路径可能产生不同边界，因此元数据中应记录实际使用的 mask 来源；当前代码主要记录检测和透视信息，后续可把这一项补入。

## 3. 从四个角点到单应矩阵

平面目标上的点可用齐次坐标表示。透视变换满足：

```text
[x', y', w']^T = H [x, y, 1]^T
(u, v) = (x'/w', y'/w')
```

`H` 是 `3 x 3` 单应矩阵，整体尺度不影响映射，因此有 8 个自由度。四组不共线的点对恰好提供 8 个独立约束。

项目先按左上、右上、右下、左下顺序排列源四边形，再根据边长或可选物理宽高比确定目标矩形尺寸，最后调用 OpenCV：

```text
H = getPerspectiveTransform(source_quad, destination_rect)
front = warpPerspective(image, H, output_size)
```

这个方法依赖“目标近似平面”。若屏幕弯曲、纸张卷曲或物体本身有显著三维形变，一个全局单应矩阵无法同时校正所有区域。

## 4. lite 后端：轮廓近似优先

轻量后端的流程更直接：

1. 选择最大可用 mask；
2. 清理 mask 并找到主轮廓；
3. 计算凸包；
4. 使用 `approxPolyDP` 尝试得到四个顶点；
5. 若未得到稳定四边形，回退到 `minAreaRect`；
6. 排序角点并计算 H。

`approxPolyDP` 用容差控制多边形简化程度。容差过小可能保留太多噪声顶点，过大可能切掉真实角。最小外接旋转矩形更稳定，但会把不规则或强透视轮廓强行矩形化。

lite 后端适合目标完整入画、接近正视、轮廓较干净的情况。README 将它描述为更轻量，但当前仓库没有保存运行时间，本文不引用速度数字。

## 5. full 后端：处理缺角、贴边和强透视

完整后端包含更多几何候选与评分：

- 保留最大连通域、填洞和 mask 收缩；
- 从轮廓/凸包估计自由四边形；
- 通过支撑线构造外包四边形；
- 识别轮廓是否接触图像边界；
- 对缺失边或角进行支撑线补全与混合；
- 比较候选四边形对 mask 的覆盖、IoU、长宽比等；
- 最终仍保留支撑线和 `minAreaRect` 回退。

### 5.1 支撑线的直觉

对某个方向的单位法向量 `n`，轮廓点投影 `n dot p` 的最小/最大值定义两条支撑线。多组方向的支撑线相交，可以构成包住轮廓的平行四边形或自由四边形。

当目标角点因遮挡消失时，直接从轮廓寻找四个顶点会失败；支撑线仍可能利用可见边方向推断交点。但如果可见边本身很短或 mask 大幅错误，这种推断也会失稳。

### 5.2 贴边目标为什么特殊

目标被图像边界裁切时，mask 轮廓会沿图像边形成一条“假边”。full 后端会检测这种接触，并把自由四边形与支撑线补角结果组合。它的目标是避免把图像边界误当目标真实边界。

这是一组工程启发式，不是已经证明在所有贴边场景正确。需要带真实角点标注的 clipped-case 数据才能评估。

## 6. 图像推理入口的完整输出

检查到的图像默认配置为：

```text
imgsz = 1280
conf  = 0.25
iou   = 0.50
retina_masks = true
perspective backend = full
quad method = free_quad
```

单图或目录处理会：

1. 收集支持的图片后缀；
2. 运行 YOLO 实例分割；
3. 将 mask 恢复到原图；
4. 选择透视后端和四边形方法；
5. 生成 mask 叠加、四边形叠加和正视图；
6. 生成左侧几何/右侧正视图的对比 panel；
7. 保存每图 method、尺寸、耗时和检测摘要 JSON。

输出开关彼此独立，可以只保存需要的证据。最有诊断价值的组合是：原图、mask overlay、quad overlay、front view 和 metadata JSON 同时保留，因为它们能区分“分割错”“拟合错”和“warp 参数错”。

## 7. 视频推理不只是循环调用单图函数

视频入口逐帧执行分割与透视，并写入固定尺寸的视频。它还处理：

- 源 FPS 与播放/保存 FPS；
- 固定输出画布和 letterbox；
- 是否显示推理 FPS；
- 透视失败时回退到原图或 mask overlay；
- 视频 writer 的编码器和尺寸约束。

当前流程主要是逐帧独立估计四边形，没有看到显式时序平滑。即使每帧角点误差很小，独立估计也可能在视频里表现为抖动。未来应保存每帧四角坐标，评估静态目标下的角点标准差和正视图边缘抖动。

## 8. 数据管线如何为实例分割服务

仓库提供从数据到训练的工具：

| 工具 | 输入 | 输出/作用 |
|---|---|---|
| 视频抽帧 | MP4 等视频 | 带间隔控制的训练候选帧 |
| Labelme 转换 | 图片 + 同名 JSON | YOLO segmentation polygon 标签 |
| Label Studio 转换 | 导出标注 | YOLO 数据集结构 |
| 数据划分 | 标注条目 | train/val/test 与 data YAML |
| 多边形增强 | YOLO mask 标签 | 同步变换图像与实例 polygon |
| 伪标转 Labelme | 模型预测 | 可人工复核/修改的 JSON |

检查到的 Labelme 转换默认按 `0.90/0.05/0.05` 划分，随机种子为 42，类别为 `table`。这只是脚本默认值；仓库没有数据集，无法确认实际训练是否使用该划分。

增强脚本对图像和 polygon 同步执行翻转、90 度旋转、仿射/透视变换和光度变化。几何增强既可以直接变换 polygon，也可以先 rasterize 为 mask、warp 后再提取轮廓。后者对裁切和复杂交集更稳，但会引入栅格化误差。

## 9. 训练/验证/预测的工程记录

YOLO 脚本支持 `train、val、predict` 三种模式，并根据任务 preset 选择数据、模型和输出目录。训练时保存：

- run ID 与开始/结束时间；
- 模型配置和实际解析权重；
- data YAML、epochs、batch、imgsz、device、workers；
- Python、平台和 Ultralytics 版本；
- train log、run metadata 和 best weight 副本。

预测模式可保存带类别/置信度、mask 轮廓和质心的图像，以及结构化 JSON。代码还提供实例重叠去重。

这些记录接口设计得较完整，但当前树只包含几种通用预训练模型，没有项目训练得到的 best weight、训练输出或预测结果。通用预训练文件的存在不能证明本项目已完成训练。

## 10. 当前结果边界

README 描述了 `data、outputs、reports` 目录，但当前提交的递归文件树中没有这些数据和结果。也没有：

- 输入图片或视频；
- 目标 polygon 标注；
- 项目 best checkpoint；
- mask、quad、front view 或 panel；
- metadata JSON；
- 训练/验证指标；
- full 与 lite 的速度/几何对比；
- 自动化测试。

因此本文不能展示真实正视化效果，也不能声称 full 更准、lite 更快或正视化改善了下游 OCR。当前可核验成果是算法和工程链本身。

## 11. 怎样评估“矫正是否正确”

只看正视图“像不像矩形”不够。建议建立四层指标：

1. **分割层**：mask IoU、边界 F-score；
2. **角点层**：四角像素误差和角点重投影误差；
3. **几何层**：正视图边缘直线度、长宽比误差、内部网格畸变；
4. **下游层**：相同 OCR/检测器在原图与正视图上的准确率变化。

full/lite 对比必须使用同一 YOLO mask，才能把差异归因于几何后端。还应单独统计完整入画、缺角、贴边、强透视和误分割案例，并记录回退方法标签。

视频需要增加时序指标：角点抖动、输出边缘抖动、透视失败率和回退连续性。

## 12. 当前工程风险

- README 提到的统一配置文件没有出现在当前树中，部分工具仍含机器相关默认路径；
- 没有依赖清单或 lockfile，OpenCV/Ultralytics 行为无法锁定；
- 空 mask、极小 mask、自交四边形和近共线角点需要系统化测试；
- 目标不是严格平面时，全局单应变换会产生不可避免的局部误差；
- 视频没有明确的时序稳定策略；
- 训练数据、权重和输出没有形成可追溯结果包。

## 13. 下一步

下一次最有价值的更新，是选择一组可公开的完整、贴边和缺角样例，为每张图保存：输入、人工 polygon、YOLO mask、full/lite 四边形、正视图、元数据与角点误差。然后在固定硬件和分辨率下比较运行时间，并用相同下游 OCR 评估正视化是否真的带来收益。

这个项目展示了一个值得复用的设计：深度学习负责把目标从背景中分离，传统几何负责把可解释的 mask 转成单应矩阵。两者之间以明确的二值 mask 和四边形契约连接，比让一个黑盒直接输出“校正图”更容易检查和替换。现在缺少的不是更多方法名，而是一组把 mask、四边形和结果绑定起来的公开证据。
