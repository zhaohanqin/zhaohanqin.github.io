工业仪表、色谱或过程界面的截图包含大量对人直观、对程序却难以直接使用的信息。这个项目的目标是把图像中的表格、曲线、坐标轴、峰值和文本组织成稳定的结构化输出，供后续分析程序消费。

## 技术栈与问题拆解

项目以 Python 为主，组合了图像预处理、表格/曲线解析、OCR、坐标轴标定、峰值处理和 JSON 输出。面对的是一类典型问题：同一张图中既有布局结构，也有数值语义，单一模型往往无法覆盖全部步骤。

## 管线原理

主链路可概括为：`截图输入 -> 区域与布局识别 -> 表格或曲线提取 -> OCR/坐标轴解析 -> 峰值与数值处理 -> JSON 契约输出`。不同阶段通过配置衔接，使项目能够针对不同图像版式选择相应策略；当某个阶段失败时，也可以输出降级信息而不是伪造完整结果。

## 为什么使用分阶段设计

将视觉定位、文字识别、坐标换算和业务判断拆开，有利于调试与替换。例如，曲线分割模型可以升级，而输出 JSON 字段保持稳定；这使后续程序不必绑定某个具体识别模型。项目也包含针对蓝线、红线以及不同处理方法的独立模块和比较脚本。

## 面向工程的价值

这不是单纯的“识别一张图片”，而是在建立一份可追溯的数据合同。对于需要批量处理实验截图、仪器报表或过程曲线的场景，稳定的中间结构比一次性展示结果更容易维护和复核。

## 当前边界

训练权重、内部样本和端到端基准不在公开范围内。虽然仓库存在分析与比较脚本，缺少完整原始输入输出包时，不能据此发布准确率、模型排名或性能结论。
