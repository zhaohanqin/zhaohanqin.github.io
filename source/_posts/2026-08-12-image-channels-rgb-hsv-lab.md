做图像处理时，最先遇到的"选择题"往往是：这张图该用哪个颜色空间、处理哪个通道？本文把图像通道的本质、RGB / HSV / Lab 三个常用颜色空间的含义与数值范围、以及"什么任务选什么空间"的决策逻辑讲清楚。

一句话记忆：

- **RGB：机器怎么显示颜色**（红绿蓝三种光的强度）；
- **HSV：人怎么描述颜色**（色相、饱和度、明度）；
- **Lab：人眼怎么感知颜色差异**（亮度、绿红轴、蓝黄轴）。

## 1. 图像通道的本质：每个像素位置上的一层数值信息

图像可以看作一个二维像素矩阵，每个像素保存一个或多个数值。这些数值按含义分成不同的"层"，每一层就是一个**通道**：

| 图像类型 | 形状 | 通道含义 |
|---|---|---|
| 灰度图 | H × W | 每个像素一个明暗值 |
| RGB 图 | H × W × 3 | R 红色、G 绿色、B 蓝色 |
| RGBA 图 | H × W × 4 | 颜色 + A 透明度 |
| 多光谱图 | H × W × N | N 个波段 |

关键认识：**通道不一定代表颜色**。深度（Depth）、掩膜（Mask）、类别编号（Label）、置信度（Confidence），甚至卷积神经网络里的特征图，都是通道。通道的本质是"这一层数值在描述什么信息"。

## 2. RGB：显示设备的语言

RGB 是加色模型：光越加越亮，三种光都没有是黑色，三种光都最强是白色。8 位图像中每个通道取值 0~255。

| RGB 值 | 颜色 |
|---|---|
| (255, 0, 0) | 红 |
| (0, 255, 0) | 绿 |
| (0, 0, 255) | 蓝 |
| (255, 255, 255) | 白 |
| (0, 0, 0) | 黑 |
| (255, 255, 0) | 黄 |

单独看 R 通道：红色区域亮、其余区域暗；G、B 同理。灰度转换公式 $Gray\approx 0.299R+0.587G+0.114B$ 中绿色权重最高，正对应人眼对绿色更敏感。

RGB 最大的问题是**颜色和亮度耦合**：同一块红色，亮红 `(230,30,20)` 和暗红 `(80,10,8)` 的 R/G/B 数值差别很大。因此光照一变，用 RGB 阈值找颜色就不稳定——这正是要引入 HSV、Lab 的原因。

## 3. HSV：按"是什么颜色"组织

HSV 把颜色拆成三个分量：

| 通道 | 含义 | 直觉 |
|---|---|---|
| H（Hue） | 色相，颜色种类 | 这是什么颜色 |
| S（Saturation） | 饱和度，颜色纯度 | 颜色纯不纯 |
| V（Value） | 明度 | 颜色亮不亮 |

### H 是环形的

标准 HSV 中 H 取 $0°\sim360°$：0°/360° 是红、60° 是黄、120° 是绿、240° 是蓝。因为 H 是环形的，**红色跨越两端**。

OpenCV 的 8 位 HSV 把角度压缩到 0~179，所以：

| OpenCV H | 颜色 |
|---|---|
| 0 / 179 附近 | 红 |
| 30 附近 | 黄 |
| 60 附近 | 绿 |
| 120 附近 | 蓝 |

检测红色通常要两个区间：

```python
lower_red1 = (0, 80, 80)
upper_red1 = (10, 255, 255)
lower_red2 = (170, 80, 80)
upper_red2 = (179, 255, 255)
mask = cv2.inRange(hsv, lower_red1, upper_red1) | cv2.inRange(hsv, lower_red2, upper_red2)
```

### 为什么 S 和 V 不能省

- 低饱和度区域（灰、白、黑）的 H 没有明确意义；
- 过暗区域颜色不可靠；
- 所以颜色分割通常要 `H 在目标范围 + S 足够高 + V 不太低` 三个条件一起用。

### V 不是感知亮度

V 定义为 $V=\max(R,G,B)$，纯红、纯绿、纯蓝的 V 都是 255，但人眼感知亮度不同。这是 HSV 的一个局限。

## 4. Lab：按"人眼感知差异"组织

Lab（CIELAB）的三个通道：

| 通道 | 含义 |
|---|---|
| L | 感知亮度（0 黑 ~ 100 白） |
| a | 绿 ↔ 红方向（负绿、正红） |
| b | 蓝 ↔ 黄方向（负蓝、正黄） |

Lab 最大的价值是**亮度和颜色分离得更干净**，并且颜色距离更接近人眼感知。

注意 OpenCV 的 8 位 Lab 范围不同：

```text
L: 0~255
a: 0~255，中性点 = 128（a<128 偏绿，a>128 偏红）
b: 0~255，中性点 = 128（b<128 偏蓝，b>128 偏黄）
```

所以判断偏色时**和 128 比较，不是和 0 比较**。

## 5. 三个空间的核心区别

| 空间 | 组织方式 | 适合回答的问题 |
|---|---|---|
| RGB | 红/绿/蓝光强度 | 显示、存储、深度学习输入 |
| HSV | 色相/饱和度/明度 | 这个像素是什么颜色？怎么找红色/黄色/绿色目标？ |
| Lab | 亮度/绿红轴/蓝黄轴 | 两个颜色看起来差多少？图是否偏红偏绿偏蓝偏黄？如何增强亮度不破坏颜色？ |

### RGB 与 HSV

同一个红色苹果在不同光照下 RGB 差异很大，但 H 仍落在红色附近，只是 S、V 变化。所以颜色分割用 HSV 更稳。

### RGB 与 Lab

RGB 里单独增强 R/G/B 容易偏色；Lab 里只增强 L 通道，a、b 不动，颜色更自然。

### HSV 与 Lab

HSV 回答"是什么颜色"；Lab 回答"颜色差异多大、怎么校正"。Lab 更适合色差计算、白平衡、工业颜色检测。

## 6. 常见通道类型速览

| 类型 | 通道 | 用途 |
|---|---|---|
| RGB/BGR | R、G、B | 显示/存储/深度学习（OpenCV 默认 BGR） |
| RGBA | +A | PNG 透明、抠图、合成 |
| HSV/HSL/HSI | H、S、V/L/I | 颜色检测、调色 |
| YCbCr/YUV | Y 亮度 + Cb/Cr 色度 | JPEG/视频压缩、肤色检测 |
| Lab | L、a、b | 增强、校色、色差 |
| CMYK | C、M、Y、K | 印刷 |
| Depth | D | 三维距离 |
| Mask/Label/Confidence | — | 分割、类别、置信度 |

JPEG 转 YCbCr 的原因值得记住：**人眼对亮度更敏感、对色度不敏感**，所以保留较多 Y、减少 Cb/Cr 就能在视觉损失很小的情况下压缩体积。

## 7. 按任务选择通道

| 任务 | 推荐 |
|---|---|
| 按颜色找目标 | HSV（H + S + V） |
| 增强亮度和对比度 | Lab 的 L（或 YCbCr 的 Y） |
| 修正偏色 | Lab 的 a/b |
| 计算颜色差异 | Lab |
| 边缘/轮廓检测 | Gray / L / Y |
| 压缩与视频 | YCbCr / YUV |
| 透明合成 | Alpha |
| 三维空间感知 | Depth |
| 遥感植被分析 | NIR + Red（NDVI） |

典型颜色分割流程：

```text
BGR 图 → 转 HSV → 设 H/S/V 阈值 → 二值 Mask → 形态学 → 找轮廓
```

典型图像增强流程：

```text
BGR 图 → 转 Lab → 只增强 L（直方图均衡/CLAHE）→ 合并 a/b → 转回 BGR
```

## 8. OpenCV 注意事项与常见误区

1. **BGR vs RGB**：`cv2.imread()` 默认返回 BGR，用 Matplotlib 显示前要 `cv2.cvtColor(img, cv2.COLOR_BGR2RGB)`，否则颜色错乱；
2. **HSV 范围**：OpenCV 是 H:0~179、S:0~255、V:0~255，不是 0~360/0~1；
3. **Lab 中点**：a/b 的中间值是 128，不是 0；
4. **uint8 溢出**：直接对通道做减法会环绕，先转 `int16`、再 `clip`、再转回 `uint8`；
5. **别只靠 H**：低饱和度区域 H 不稳定，必须配合 S、V；
6. **别分别增强 RGB**：对 R/G/B 分别直方图均衡会偏色，应只增强 L 或 Y；
7. **别把 a/b 的亮暗当亮度**：a 亮表示偏红、b 亮表示偏黄，不代表图像明暗。

## 9. 小结

通道的本质是"每个像素位置上的一层数值信息"。RGB 用红绿蓝组织颜色、HSV 用色相饱和度明度组织颜色、Lab 用亮度与两个颜色轴组织颜色，YCbCr 用亮度和色度组织颜色。实际使用时不必死记名字，而是问自己三个问题：

1. 这个通道代表什么？
2. 它适合解决什么问题？
3. 它的数值范围是多少、处理它会改变图像的什么属性？
