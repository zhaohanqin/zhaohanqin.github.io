薄层色谱（TLC）板上的斑点位置常用迁移比 `Rf` 描述。人工测量需要辨认点样线、溶剂前沿和每个斑点中心，再按距离计算。图像自动化的难点不在最后那条除法，而在于前面的每一步都可能改变测量坐标：板子是否找准、透视是否展开正确、起止线是否稳定、斑点质心是否可信。

这个项目把全景图到 Rf 的过程拆成可配置流水线：板实例分割、几何筛选、自由四边形透视展开、起止线定位、斑点实例分割、泳道归属、Rf 计算和 JSON/可视化输出。

## 如何运行与获得输出

全景图使用 `main_withyolo.py --image <图或目录> --output-dir <目录> --plate-backend yolo`；已展开单板使用 `main_warped_detect.py`；只需要分板/透视时使用 `engine/only_plate_yolo.py`。默认 manual 划线可切换为 auto 或半自动模式。典型输出是 `*_only_plate.png`、`*_result.png`、可选 `*_response.png` 和同名 JSON。

想先看输出长什么样，可以直接打开仓库里的 `results/20260717-170515/`（说明见 `results/README.md`）：那里有一份输入、中间过程和最终 JSON 的完整样例，不需要本地数据和模型权重。

## Rf 的定义与坐标约定

在展开后的正视图中，图像 `y` 坐标向下增大。设：

- `y_start`：点样线位置，通常靠近板底；
- `y_end`：溶剂前沿位置，通常靠近板顶；
- `y_spot`：斑点质心纵坐标。

代码计算：

$$
\mathrm{total\_travel}=y_{\mathrm{start}}-y_{\mathrm{end}},\qquad
\mathrm{spot\_travel}=y_{\mathrm{start}}-y_{\mathrm{spot}},\qquad
R_f=\frac{\mathrm{spot\_travel}}{\mathrm{total\_travel}}
$$

只有质心位于起止线之间的斑点才进入结果。理想情况下 `Rf` 在 `[0,1]`，但它的可信度完全依赖三个 `y` 坐标是否在同一、正确的板坐标系中。

如果直接在倾斜全景图上量像素距离，近端和远端比例不同，斑点与基线也可能不平行。因此项目先把每块板单独找出并变换到正视坐标，再做测量。

## 阶段一：从全景图分离 TLC 板

当前配置把 YOLO 实例分割作为默认板后端，同时保留 SAM3 文本提示分割作为可选路径。

### 为什么需要实例 mask

检测框只能给出近似矩形，无法描述倾斜板、缺角、遮挡和背景边界。实例 mask 提供板轮廓，后续才能估计四边形、判断面积/长宽比并进行透视展开。

两个后端最终都归一化为相同数据契约：一组与原图同尺寸的二值 mask。随后统一执行：

- 最小图像面积比例过滤；
- mask extent（轮廓对包围区域的填充程度）过滤；
- 板长宽比范围过滤；
- mask 重叠去重；
- 最大板数量限制。

检查配置中，默认板后端是 YOLO；推理尺寸为 `2560`，置信阈值为 `0.35`，IoU 为 `0.50`。这些是当前配置值，不是跨数据集最优参数。

### 为什么允许两个运行环境

主程序优先在当前 Python 环境加载 Ultralytics YOLO。如果缺少依赖，可调用另一个配置的环境，通过子进程脚本传递 JSON。板分割和斑点分割都提供这种适配器。

这是一种现实的工程折中：SAM3、YOLO、OCR/数值处理可能有不同依赖组合。代价是部署配置更复杂，错误需要区分“模型失败”和“子环境/路径失败”。

## 阶段二：mask 到自由四边形正视图

传统 `minAreaRect` 总会给出一个旋转矩形，但真实板轮廓可能缺角、贴边或因遮挡形成非规则凸包。当前配置优先使用 `free_quad`：从 mask 几何中估计四条边及其交点，构造更贴近板面的自由凸四边形；必要时再回退到支撑线、轮廓近似或最小外接矩形。

在拟合前，代码可对 mask 做内收腐蚀，当前配置为 `7 x 7` 核、7 次迭代，并设最小保留面积。这用于削弱实例分割在板外产生的 halo，让四边形边缘更接近实际板面。不过腐蚀过强也可能切掉有效区域，所以它只能作为可调预处理。

确定四个角点后，使用单应矩阵 `H`：

$$
[x',\,y',\,1]^T\sim H\,[x,\,y,\,1]^T
$$

把透视四边形映射为标准正视矩形。后续起止线、泳道和斑点全部在这个 warped 坐标系中计算。

## 阶段三：起止线定位

代码支持四种模式：

| 模式 | startline | endline | 适用情况 |
|---|---|---|---|
| `manual` | 配置比例 | 配置比例 | 版式固定、优先稳定复现 |
| `auto` | 图像检测 | 图像检测 | 线条清晰、版式变化 |
| `manual_startline` | 手动比例 | 自动检测 | 点样线稳定、前沿变化 |
| `manual_endline` | 自动检测 | 手动比例 | 前沿稳定、点样线变化 |

当前有效配置默认 `manual`，从板底向上计算：

```text
startline ratio = 0.10
endline ratio   = 0.7919
```

这和部分文档仍写的 `0.1458` startline 不一致。公开文章以代码实际加载的配置为准，并把它列为文档漂移，而不是悄悄混用两个值。

自动路径会在预设纵向范围内分析明暗 profile，并对溶剂前沿提供 RANSAC 辅助：从候选边缘点拟合近似直线，限制斜率和距离，再与标记线证据按权重组合。实现保留了方法名和置信信息，便于在 JSON 中追溯本次采用了哪条路径。

## warped 与 preprocessed：两种检测域

起止线和斑点检测可以分别选择输入图：

- `warped`：原始正视展开图；
- `preprocessed`：对背景响应进行增强后的图。

这两个选择相互独立。例如，划线可以使用增强图，而斑点模型仍使用原始 warped 图。预处理用于增强弱线/弱斑对比，但也可能改变颜色和噪声分布，所以斑点权重会根据检测域选择不同版本。

当前默认两者都使用 `warped`。代码实现了响应域路径，并不等于响应域一定更准确。

## 阶段四：YOLO 斑点实例分割

斑点模型输出每个实例的 mask、边界框、类别、置信度和轮廓。代码从 mask 计算质心，并执行重叠去重。检查配置中的斑点推理参数为：

```text
imgsz = 2560
conf  = 0.25
iou   = 0.50
```

随后只保留质心位于 `[endline, startline]` 的实例。这个过滤非常重要：板外反光、文字、边框或线条即使被模型误分割，也不应直接进入 Rf 计算。

代码区分普通斑点和纵向拉长斑点的类别显示，并在结果图上绘制 mask 边缘、质心和 `Rf` 文本。仓库自 2026-08-15 的提交起已入库一份端到端样例输出图（见下文“入库的端到端样例”），但单张样例不足以给出召回率或检测精度。

## 泳道归属不是自动发现

当前主路径按板的物理宽度和配置生成固定泳道中心：默认 4 条泳道，包含起始偏移、泳道间距和半宽参数。每个斑点按横坐标分配到最近中心。

因此准确表述是“按已知板规格进行固定泳道映射”，而不是“从图像自动识别泳道”。如果不同实验板的点样位置、泳道数量或宽度变化，需要调整配置或增加真正的泳道检测。

项目另有基于纵向 profile 找峰的泳道/液滴实验代码，但不能因为文件存在就把它写成当前默认行为。

## 输出 JSON 如何保留证据链

每张输入图会形成结构化结果，核心层次包括：

```json
{
  "plate_backend": "当前使用的分板后端",
  "plates": [
    {
      "line_detect_method": "本次起止线方法",
      "startline_y_px": 0,
      "endline_y_px": 0,
      "lanes": [
        {
          "lane_id": 1,
          "droplets": [
            {
              "centroid_board_xy": [0, 0],
              "rf_value": 0.0
            }
          ]
        }
      ]
    }
  ]
}
```

上面是字段结构示意。仓库已入库的样例 `04_result.json` 给出了真实字段值：`plate_backend=yolo`、`line_detect_method=manual_lines_from_bottom`、`startline_y_px=773.1`、`endline_y_px=178.76`、`runtime_s≈1.53`，并按泳道列出每个液滴的类别、置信度、质心、Rf、迁移距离、bbox 与轮廓。项目还可输出：

- 原图上的板 mask；
- 每块板的正视展开图；
- 起止线、泳道、斑点轮廓和 Rf 标注结果图；
- 可选 line/profile 调试图；
- 每图 JSON 和批处理日志。

把 `line_image_source、spot_image_source、line_detect_method` 放入结果，是一个重要工程设计：下游不仅看到 Rf，也能知道它由哪种输入域和哪条划线路径产生。

## 误差如何逐级传递

Rf 公式简单，但最终误差可分为四层：

1. **分板误差**：mask 缺角或带入背景，导致四边形错误；
2. **透视误差**：板被拉伸/裁切，点与线的相对纵向位置改变；
3. **线定位误差**：分母 `y_start-y_end` 与迁移距离同时变化；
4. **斑点误差**：mask 漏检、粘连或质心偏移改变分子。

可以对 Rf 做一阶敏感性分析。设：

$$
R_f=\frac{y_s-y_p}{y_s-y_e}
$$

当起止线距离较小时，相同像素误差会造成更大的 Rf 变化。这也是为什么不能只报告斑点模型的 mAP，就把它等同于最终 Rf 精度；必须用标注的起止线和斑点中心直接评估最终测量误差。

## 技术栈与复现条件

| 技术 | 用途 |
|---|---|
| Python / NumPy | 数据编排、数值与结构化输出 |
| OpenCV | mask 几何、轮廓、单应变换、RANSAC、绘图 |
| Ultralytics YOLO | 板和斑点实例分割 |
| PyTorch / Transformers | 可选 SAM3 分板后端 |
| TOML | 集中配置主流程、划线和透视参数 |

复现目前仍需要外部模型权重、输入图和匹配环境。仓库没有自动化测试，也没有锁定全部依赖版本。不同脚本/文档间的默认参数漂移，说明后续需要把“生效配置”随结果一同保存。

## 结果包已有哪些、还缺什么

本次入库的样例补齐了“输入 → 中间过程 → 输出”的可视化与结构化 JSON，已经具备：

- 授权全景图、分板 mask、透视展开图与最终标注图的成套可视化；
- 每泳道每液滴的 Rf、坐标、轮廓、置信度与耗时等结构化字段；
- 可追溯的入口、分板后端、划线方法与配置参数（JSON 内记录）。

距离“可公开评测”还缺：

- 人工标注的板角点/边界，用于评估透视后的几何误差；
- 人工 startline/endline 与斑点中心，直接计算 Rf 绝对误差；
- YOLO/SAM3 在同一输入、同一筛选和同一透视后端下的受控比较；
- 弱斑、缺角、遮挡、边缘板等失败案例与多板场景；
- 模型哈希、完整环境锁定、输入清单与每图 JSON 的批量打包。

这个项目最有价值的部分，是把 Rf 测量从“一个模型输出”拆成了可追踪的几何和视觉链路。下一步不应只继续调检测阈值，而要对每一级误差建立标注和最终 Rf 误差的联系。
